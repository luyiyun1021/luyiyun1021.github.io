Sglang chunked prefill 逻辑梳理

发表于 2025-08-21 分类于 大模型 ， 推理技术 ， Sglang 阅读次数： 本文字数： 675 阅读时长 ≈ 2 分钟

1. 参数与开关

配置环境 作用
ServerArgs.chunked_prefill_size 每次预填（prefill）最多送进 GPU 的 token 数上限；≤0 表示关闭分片
ServerArgs.enable_mixed_chunk 为「边 decode 边 prefill」（mixed-chunk）提供条件；配合 pd_sep=false
envs.ENABLE_PREFILL_OVERLAP 是否允许其它 DP rank 与本 rank 并发预填

2. 关键状态变量

变量 定义处 含义
Req.extend_input_len Req.init_next_round_input() 本轮 还需要写入 KV-cache 的 token 数（扣掉已命中前缀）
Scheduler.being_chunked_req Scheduler.get_new_batch_prefill() 唯一 一个「正在分片的请求」句柄
PrefillAdder.rem_chunk_tokens PrefillAdder.__init__() 这一轮剩余的 chunk token 预算；源自 chunked_prefill_size
PrefillAdder.new_being_chunked_req add_one_req() / add_being_chunked_req() 本轮新产生的 “未填完” 请求

3. 选batch阶段：Scheduler.get_new_batch_prefill()

  1. 优先递补上一轮没填完的 being_chunked_req

  1. 遍历 waiting_queue，将请求交给 PrefillAdder.add_one_req()

    • 判断是否 需要分片：

    • 若触发分片：

      • 截断 req.extend_input_len = trunc_len

      • req.fill_ids = req.fill_ids[:prefix + trunc_len]

      • 标记 self.new_being_chunked_req = req

  2. 选batch完成后，如果 new_being_chunked_req 不为 None，转交给调度器保存：

4. 执行阶段：Scheduler.run_batch()

  • 本轮送进 GPU 的 token 就是 extend_input_len。

  • being_chunked_req.is_being_chunked 会被设为 分片计数器：

    • add_being_chunked_req() → 计数 +1

    • process_batch_result_prefill() 每次 forward 完成后 -1

5. 处理结果：Scheduler.process_batch_result_prefill()

  • 没填完 → 请求留在 being_chunked_req，下一轮 get_new_batch_prefill() 会继续填剩余部分。

  • 填完并且 max_new_tokens=0 → 立即进入释放 KV-cache 和 send-kv-cache 分支。

6. 循环与退出条件

  1. 在 下一轮get_new_batch_prefill() 里首先处理 being_chunked_req：

    • 调整 extend_input_len（剩余量）

    • 如果再次超过 rem_chunk_tokens → 再切一片; 否则最后一片填完就置 None。

  2. 当 所有片段都完成 且 max_new_tokens==0 时：

    • 正常走 req.finished() 流程

    • 从树缓存中回收节点；being_chunked_req 被彻底消失。

7. 与 Mixed-Chunk（边 decode 边 prefill）协作

当 self.is_mixed_chunk 为真并且 GPU 还有 decode batch 在跑：

  1. Scheduler 会把当前 running batch 里的 decode 请求先 滤空，

  2. 然后把拆分后的 prefill 片段 混到 decode batch 中一起进 GPU，

  3. decode 端 token 返完后再在下一轮继续剩余 prefill。

8. 对资源预算的影响

  • PrefillAdder._prefill_one_req() 会同步扣减

    • rem_total_tokens：总 token 预算

    • rem_input_tokens：正在填 KV 的 token 预算

    • rem_chunk_tokens：本轮可用的 chunk token 预算

这样可保证 单轮 不会送超过 chunked_prefill_size 的 token，也避免解码耗尽 KV-cache。

9. 小结 - 整体状态机

  • ChunkedReq 只会同时存在一条。

  • 直到所有片段完成，它都会在 “Add → GPU → Check → Add” 环里循环。

  • Mixed-chunk 时 decode / prefill 会在同一 GPU batch 中穿插。
