以 KV-Cache 为中心的 PD 分离式架构

发表于 2025-08-20 分类于 大模型 ， 推理技术 ， Sglang 阅读次数： 本文字数： 684 阅读时长 ≈ 2 分钟

KV Cache 的用途

  1. KV Cache 是推理的中间结果

  2. KV Cache 可以复用，以存储代计算

  3. 复用场景：

    • Prefix Cache:请复用，节省算力

    • P/D分离：跨机复用，推理分布式化

以KV Cache 为中心

  1. 以 KV Cache 决定哪个节点来处理请求

    • 增加 Prefix Cache 命中长度，节省更多算力

  2. 以KV Cache 接请求的 P/D阶段

    • Prefill 完成计算 → KV Cache 传输到 Decode → Decode 基于 KV Cache,继续自回归生成

KV存储的需求和挑战

需求：

  1. 命中率高：大容量，全局数据拓扑感知

  2. 性能高：低延迟，高吞吐

  3. 无感接入：不干扰推理主流程

挑战：

  1. 大容量设备(DRAM/SSD)性能不足

  2. KV Cache 总量，难以保障索引改查性能

  3. 如何充分异步，避免干扰主流程

AttentionStore

整体架构

AS Master

  • 全局索引构建

  • 全局索引查询和同步

  • 全局索引管理(GC、屏蔽等)

AS Agent

  • 单机整体索引构建

  • 单机内存和SSD KV Cache读写

  • 单机缓存淘汰管理等

  • 单机引擎元数据持久化

主要数据流

充分利用低速设备

  1. 叠加SSD读写能力：

    • KV Cache 打散到多个 SSD

    • 并行读出

  2. 加速内存->显存拷贝：

    • 默认步骤：内存→临时锁页内存→显存

    • 优化后：锁页内存→显存

  3. 流水线并行：

    • 『SSD -> 内存』、『内存 -> 显存』并行执行

全局拓扑感知

纯正排索引(节点 -> KV Cache)：查询慢，O(N*L)查询效率

纯倒排索引(KV Cache -> 节点)：更新慢，Agent 上报冲突严重

  1. 双索引分离读写路径：

    • 写：Agent→ Master 正排索引

    • 读：调度器内存倒排索引，O(N*L)→O(L)

  2. 增量事件入队列，实时协同双索引

    • 无阻塞设计：Agent、Master、调度器解耦

    • 自愈能力：自动断点续传

  3. 一致性保障：

    • 正排索引作为唯一数据源

    • 倒排索引作为派生状态

消除对推理主流程的干扰

以传输为例，有以下干扰：

  1. 传输动作插入到主流程，直接增加间隙

  2. P/D因为传输产生耦合：

    1. Prefill等待传输完成，才能释放显存

    2. Decode等待传输完成，才能执行请求

消除干扰：

  1. 异步传输：线程异步执行传输，事件驱动（传输Worker卸载到C++,实现Python中真正并行)

  2. 异步发送：内置DRAM缓冲区，发送端完成D2H即可释放显存

  3. 异步接收：引擎侧将待传输缓冲在队列中，不阻塞其他请求执行
