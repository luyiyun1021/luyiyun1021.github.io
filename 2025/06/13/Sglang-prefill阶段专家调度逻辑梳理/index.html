    1. 各层都是独立的，需要有独立的负载均衡

  2. prefil 均衡
    1. 机器级别负载均衡：将专家组均匀分布到每台机器上；
    2. 为每个机器上的专家分配冗余专家；
    3. 卡级别均衡：将机器上的专家均匀分布到每张卡上；
  3. decode均衡
    1. 根据专家负载分配冗余专家；
    2. 卡级别均衡：将专家均匀分布到每张卡上；

详细逻辑梳理

  • server端增加rearrange_experts endpoint, 发送请求给tokenizer_manager.rearrange_experts(obj, request), 加上锁,不再接收新请求, 调用rearrange_experts_communicator, 把这个重排请求发送给dp_controller, 再由它转发给所有Scheduler
  • Schduler在事件循环中接收到RearrangeExpertsReqInput, 在ep_rank 0 上把 need_rearrange_experts 设为 True
  • Schduler在prepare_dp_attn_batch阶段把 ep_rank 0 的 num_tokens 设成 REARRANGE_EXPERT_MAGIC_NUM, 对所有的 ep_rank 的 local batch 的 token 数量进行 all_gather 操作, 获得 global_num_tokens, 如果发现global_num_tokens 中 ep_rank 0 的 tokens数量是 magic num, 触发专家重排execute_rearrange_experts, 调用tp_worker.rearrange_experts->model_runner.rearrange_experts->model_runner.do_rearrange_experts
    • rank_expert_list, tokens_per_expert_stats_list = self.model.model.caculate_new_expert_rank_table()
      • rank_expert_list, _, _ = rebalance_experts(self.tokens_per_expert_stats_list, num_replicas, num_groups, num_nodes, num_gpus), 调用eplb的rebalance组件
        • 参数说明
          • tokens_per_expert_stats_list: [total_experts_num], 下标代表expert id号，内容代表次数, 表示每个专家被当前rank上的token命中的次数, 通过all reduce获得全局的负载统计
          • num_replicas = self.config.n_routed_experts + self.redundant_experts_num: 物理专家数量，它是配置中路由的专家数（n_routed_experts）加上冗余的专家数（redundant_experts_num）。
          • num_groups: 专家组的数量。
          • num_nodes: 服务器节点的数量，其中节点内网络（如NVLink）较快。
          • num_gpus: GPU的数量，必须是num_nodes的倍数
        • 返回重排后物理专家到逻辑专家的映射
      • rearrange_succ, loaded_weight, exist_fatal_error, message = self.update_experts_weight_from_disk(rank_expert_list, ep_rank)
        • 我们通过 ep_rank_to_expert_id_list， expert_id_to_ep_rank_array，expert_in_rank_num_list，tokens_per_expert_stats_list 4张表格，重构ep rank 和 expert id的关系，并且记录负载状态。（* list 表示1为数组， * array 表示二维数组）, 物理专家个数 = 256 + 冗余专家数量, 逻辑专家个数 = 256
        • set_rank_expert_table 更新下面的表格
        • 通过比较new_expert_ids和 old_expert_ids, 即eplb返回的重排后物理专家到逻辑专家的映射, 获得need_to_reloadlist, 包含(layer_id, new_expert_id)对, 即需要重新加载的逻辑专家权重的名字
        • 对于在物理expert上需要交换的情况, 调用 load_expert_weight_from_disk
          • https://github.com/zhaochenyang20/Awesome-ML-SYS-Tutorial/blob/main/sglang/online-update-weights/readme.md
          1. 创建 sglang 的 DefaultModelLoader, 指定 loadTensorPatterns: "model.layers.{}.mlp.experts.{}.".format(layer_id, expert_id)
          2. 通过 get_weight_iter 获取权重迭代器, 内部调用loader._get_weights_iterator, 调用safetensors_weights_iterator获得对应的name, param
          3. 使用 model_load_weights 加载通过get_weight_iter获得的新的模型权重, 内部调用model.load_weights﻿
            i. 调用EPMoE.make_expert_params_mapping获得(param_name, weight_name, layer_weight_name, [expert_id], shard_id)按
            1. for expert_id in range(num_experts),
            2. for layer_id in range(num_hidden_layers),
            3. for shard_id, weight_name in [("w1", ckpt_gate_proj_name), ("w2", ckpt_down_proj_name), ("w3", ckpt_up_proj_name)]
              三层嵌套循环的映射表, 其中[expert_id]是通过expert_id_to_ep_rank_array[layer_id][expert_id]获得的某个逻辑专家id, 在哪些物理专家上被部署的列表
              ii. 根据传入的weights中的name, 通过expert_params_mapping[layer_id * nums_expert_params_per_layer:(layer_id + 1) * nums_expert_params_per_layer]获得某一层的每个逻辑专家的mapping, 遍历这个mapping, 筛选出layer_weight_name和 name匹配的, 调用EPMoE.weight_loader把传入的逻辑专家的weight依次加载到[expert_id]列表中的物理专家上, 即self.named_parameters()[param_name][expert_id]
            • DeepseekV2MoE::DPEPMoE 初始化时传入的num_experts=config.n_routed_experts + global_server_args_dict[“re_ep_size”], 因此对于模型来说, 它拥有288个物理专家
